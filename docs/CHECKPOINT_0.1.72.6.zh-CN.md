# 0.1.72.6 · 栏目、渐进载入与倍率修复

本轮实现用户的五项需求，完整移植仍未完成。

## 已实现

- 导入从逐张串行哈希+缩略图解码，改为两路有限并行完整 SHA256/EXIF 方向尺寸读取，按自然顺序合并去重。保留内容去重和源文件只读；导入阶段不解码像素。跨栏目导入可复用路径、长度、修改时间均未变化的元数据。
- 重启立即恢复台面布局，不再阻塞等待全部已放置照片的 2200px 高清层。仅可见台面按屏幕尺寸准备，镜片高清独立按需读取；文件菜单可重试。
- 底栏启用横向滚动条、鼠标滚轮和左右翻页。触摸横向拖动不再立即被袋口飞行动画抢占指针；离屏回收时释放 XAML 缩略图引用。
- 栏目可新建、选择和重命名，新栏目为空。文件夹替换和追加导入仅作用当前栏目；相册照片列表、幻灯片和平铺使用当前栏目。台面共用。
- 「移出栏目」和右键移除只删除当前栏目的照片引用，保留台面/其他栏目/原图。照片元数据可继续服务已摆放的散片和相册。
- 布局 schema 2；schema 1 迁入栏目一，保存当前栏目和独立成员。旧版安全会话机制拒绝覆盖较新布局。
- 普通镜片原来固定 1.5×，只在 Space 时应用四档。现普通/凑近均实际使用所选 1×/2×/4×/8×，Space 仅改变孔径与位置，灯开关独立。
- 保留两路缩略图、两路预览、两路光学构建与缓存限额；台面准备批次上限 4。缓存目录统计从每次写入全量扫描改为增量记账、每 64 次写入复核，超限时立即淘汰。没有以占满所有硬件为目标。

## 冷载入实测

同一开发机、相同公开 NASA JPEG 数据集、每轮空白隔离数据目录；四组均退出 0、无 crash.log。导入阶段现为哈希/元数据，缩略图与台面逐步显示，不能将它与上版「全部缩略图完成」当作同一阶段。GPU 准备使用同一个可见台面准备入口；新版底栏增加控件，台面可用高度有所缩小。未清空操作系统文件缓存，不代表物理硬盘完全冷读。

|---|---:|---:|---:|---:|---:|
|10|92.44|257.57|3641.28|1.78|183.06|

|500|506.41|11497.64|3479.46|61.65|507.75|
|1000|887.64|21589.62|3624.44|105.30|696.41|

0.1.72.5 的 1000 张对应记录为导入 8847.49ms、GPU 准备 48982.87ms、Draw CPU P95 153.35ms、内存峰值 672.69MiB。新版导入约快 10 倍，可见 GPU 准备约快 2.27 倍，但内存峰值约高 3.5%；100 张 Draw P95 也略高，不能声称所有阶段均改善。1000 张点灯 CPU P95 本轮约 132.28ms，**仍未达到大图库全阶段 60FPS**。

1000 张进程采样的 I/O 传输计数约读 114.30MiB、写 355.30MiB；这是进程 I/O API 计数，不是物理磁盘吞吐。CPU 总时间、CPU 缓存/GPU 纹理估算和进程 I/O 均记录在 benchmark JSON，未测得硬件 GPU 利用率，不宣称所有硬件满载。性能目标是缩短等待、维持响应并限制资源，而非把 CPU/GPU/内存/硬盘都推到 100%。
