# 0.1.75.2 · 全部底栏照片常驻，移除相册

原作者：**抖音 @怕蛇LightTable**；[原项目](https://github.com/fuyuan9972-svg/LightTable)。基线仍为 v0.1.75 `827ca13d947e4472675bbe409837c0188a9385d9`。这是用户对底栏逻辑及功能范围的明确修正，覆盖 0.1.75.1 的取片隐藏与相册功能。

## 正确行为

- 每个栏目底栏始终显示全部照片。100 张图库、60 张在台面：底栏仍为 100 张，60 张原位显示「已上台」，其余 40 张保持原顺序和位置。
- 上台或移出台面只修改状态标记，保持底栏项目对象、缩略图与滚动位置，不重新构建整个列表。
- 台面选中照片按 Delete：只移出台面，底栏照片保留并清除上台标记。底栏选中照片按 Delete 或垃圾桶：从当前栏目移除，同时移除该栏对应散片，其他栏目和磁盘原图保留。
- 相册按钮、菜单、编辑器、整页上台、底栏相册项目和相册 GPU 绘制实现均已移除。旧布局解码模型仅用于迁移，不再提供相册功能。
- 旧相册各袋格照片引用追加到原栏目，去重但不打乱已有照片顺序；旧相册结构先持久化为 `layouts/before-album-removal/<时间>-<随机ID>.json` 独立备份。备份失败不会移除相册数据。Mac 导入保留原 JSON，并进行同样转换。
- schema 4 防止旧版覆盖新版布局。独立栏目、可拖分隔线、普通/凑近真实四档倍率、Space 与灯光独立、加载优化和原作者署名继续保留。

## 验证

- 核心测试 113/113，包括 100/60/40 顺序、移出台面后成员不变、跨栏目旧相册转换、独立备份、幂等转换以及备份失败不修改数据。
- Release 开发构建零警告零错误；开发原生第二轮 30/30。旧两项相册验收被 100/60 常驻底栏和照片布局往返取代，未把历史相册测试冒充新版功能。
- 原生真实 ListView 100 张、60 个标记/40 个无标记；所有项目对象、顺序、滚动位置 11566.4 不变。移出台面后 100 张/59 个标记，新 Store 恢复一致。
- 实际 GUI 使用 100 个隔离 JPEG 测试引用：100/60；滚动到后 40 张均仍存在、没有上台标记；第 90 张拖上台后 100/61 且原位标记，Delete 后 100/60 且原位清除。截图见 [底栏交界](evidence/checkpoint-0.1.75.2/tray-100-60-boundary.png)。观片菜单无相册入口。
- 首轮原生两项检查失败：一个诊断直接改栏目成员后未发 LibraryChanged，另一个在虚拟列表范围未稳定时测量滚动位置。补全生产导入相同的通知，并等到实际列表范围稳定后复测通过；首轮原报告保留。
- 最终便携包 30/30、退出 0；安装沙箱两轮安装/卸载/重装通过，已安装程序 30/30、退出 0；布局保留、原生产安装注册项与快捷方式未变。未冒充干净 Windows 或真实生产 AppId 覆盖升级。

本次没有声称解决大图库 60FPS、完整 P3/FP16、多屏/所有触摸/格式、干净 Windows、实际生产安装覆盖升级、长期稳定或真实驱动故障。这些仍是已知限制。本版未签名，SHA256 只验证文件完整性。
